# 결과와 평가 방법


결과는 `runs/a/<suite>/` 또는 `runs/b/<suite>/`에 저장됩니다. 모의 실행 폴더에는 `_mock`이 붙습니다.

| 파일 | 내용 |
|---|---|
| `report.html` | 조건별 결과, 오류, 원문, CSV 링크 |
| `config.json`, `backend_*.json` | 설정·환경·로드 시간·해시·서버 속성 |
| `eda.json` | 샘플 수, 사진/영상 비율, 크기, 파일 중복 |
| `references.json` | 실행 당시의 답안·검수 기준 복사본. 모델에는 전달하지 않음 |
| `requests.jsonl` | 요청별 설정·프레임·응답·형식 검사·시간 |
| `summary.csv`, `metrics.csv` | 조건별 요약·요청별 수치 |
| `review.csv` | 사람 평가 입력란과 답안·관찰 기준 |
| `telemetry.jsonl` | 그룹별 시간·메모리·활성 슬롯 표본 |
| `calibration.jsonl` | 컨텍스트 채우기 전 보정 요청 |
| `events.jsonl`, `server_*.log` | 시작 오류 및 서버 로그; 해당 이벤트가 있을 때 생성 |

정답은 팀이 업로드한 `answers/샘플ID.json`에서 읽습니다. 정답은 자동 생성하지 않습니다. 모델 출력은 **`keywords`, `reason`, `place_name` 3개 필드**이며 태그는 최대 5개입니다. 사람의 정답 `keywords`는 개수 제한이 없습니다. [정답 작성법](DATASET.md)을 참고하세요.

## 자동 검사: 출력 형식과 실행 성능

응답 원문을 수정하지 않고 JSON 파싱 성공, 필수 키·자료형·태그 개수·문자 길이·추가 키를 검사합니다. 실행 성공률, 요청 시간의 중앙값·p95, 메모리도 기록합니다. 실패·재시도도 전체 시도의 분모에 포함합니다. 모델 로드 실패는 별도 이벤트와 계획 대비 누락으로 표시합니다.

B는 로컬 용량 실험이므로 태그 자동 점수를 계산하지 않습니다. 허용 태그 일치율 참고값과 최종 사람 품질 평가는 [A 저장소](https://github.com/yooongZa/filename-model-quality-bench/blob/main/docs/EVALUATION.md)에서 진행하세요. B에도 응답을 살펴볼 사람 평가표를 저장합니다.

## 최종 품질: 사람 평가

원본 사진·영상과 모델 응답을 함께 보고 `review.csv`에 아래 값을 입력합니다. 허용 목록에 없는 표현도 화면에 맞는지 직접 확인합니다.

| 필드 | 입력 기준 |
|---|---|
| `reviewer` | 평가자 이름 |
| `tag_accuracy_0to2` | 0: 장면과 맞지 않음 / 1: 일부 오류·모호함 / 2: 관찰과 일치 |
| `filename_usefulness_0to2` | 0: 찾는 데 도움 없음 / 1: 일부 수정 필요 / 2: 그대로 파일명에 활용 가능 |
| `unsupported_claim_0or1` | 태그·근거·지명에 관찰로 뒷받침되지 않는 주장이 있으면 1, 없으면 0 |
| `temporal_evidence_0to2` | 영상의 행동 변화: 오류·누락 0 / 일부 1 / 충분히 반영 2. 사진·변화 없는 영상은 빈칸 |
| `notes` | 판단 이유, 수정할 태그, 모호한 표현 |

빈 태그 응답은 정확성을 빈칸, 활용도를 0으로 기록합니다. 실행 실패·형식 실패·모의 실행·B 용량 실험은 품질 비교에서 제외하고 실행 결과로 따로 보고합니다. 평가하지 않은 값은 빈칸으로 둡니다.

모든 해상도·프레임 수·출력 토큰 조건에 같은 자료와 평가 기준을 적용하세요. 결과를 섞고 조건 이름을 가린 뒤 평가하면 선입견을 줄일 수 있습니다. 일부 자료는 두 사람이 독립적으로 평가한 뒤 의견 차이를 확인하세요.

사람이 입력한 위 필드와 메모는 리포트 재생성 시 유지됩니다. 새 정확성·활용도 칸은 사람이 직접 입력하며 기존 비율 점수를 자동 변환하지 않습니다. HTML은 사람 평가 기준과 CSV 링크를 제공하며, 사람 점수를 자동 합산하거나 순위를 만들지 않습니다.

## 리포트 다시 만들기

```bash
python make_report.py runs/b/images --dataset-root data/evaluation
```

실행 당시의 `references.json`을 사용하므로 원본 정답만 수정해도 기존 실행의 참고값은 바뀌지 않습니다. 새 기준으로 비교하려면 새 실행 이름을 쓰고 모든 조건에 같은 허용 목록을 적용하세요. 과거 정답의 추가 필드는 사용하지 않으며, 원문 로그와 당시 정답 복사본은 수정하지 않습니다. 출력 규칙이 바뀌었으므로 새 실험은 새 실행 폴더를 사용하세요.
