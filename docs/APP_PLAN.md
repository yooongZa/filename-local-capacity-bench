# filename 로컬 프로그램 구현 범위

Based-On: none — 직접 대응하는 LMS 멀티모달 파일 정리 예제가 없어 기존 filename 전처리·백엔드를 재사용합니다.

완료 조건: config에서 조건 변경, v3 파일 로드, 사진·영상 분석, 원래 이름에 5개 태그 추가, 검토 후 선택 변경, 처리 파일 재분석 제외, 원본 내용 보존, 오류·충돌 표시.

설정은 기존 벤치마크 config 위에 공통 profile을 적용합니다. Colab의 Python 변수 덮어쓰기를 제거합니다. 기존 실험의 기본값과 미커밋 영상 처리 변경은 보존합니다. 로컬 앱은 순차 처리하며 모델 한 번 로드 후 재사용합니다.

파일 변경 경로: 검토된 5개 태그 → 유효한 이름 검사 → 원본 해시 재검사 → SQLite에 pending 기록 → 운영체제의 덮어쓰기 없는 rename → 완료 기록. 파일 내용 복사·편집은 하지 않습니다. 중단 시 pending 기록을 기존/새 경로와 해시로 복구합니다. 다른 프로세스의 같은 폴더 작업은 파일 잠금으로 막습니다.

| 경로 | 확인할 결과 |
|---|---|
| 정상 | 이미지·영상 분석, 5개 태그 수정, rename, 재시작 후 skip, undo |
| 실패 | 잘못된 JSON·태그 수·모델 오류·기존 대상 이름·바뀐 원본 차단 |
| 취소 | 현재 요청이 끝난 뒤 다음 파일 중단, rename은 명시적인 별도 동작 |
| 재시도 | 실패 파일 재분석, pending rename 복구, 완료 파일 skip |
| 동시성 | 분석/rename/undo 중 중복 실행 거절, 폴더 잠금 |

검증은 임시 파일·원본의 임시 복사본에서만 합니다. 실제 사용자 폴더의 파일명은 구현 검증 중 변경하지 않습니다. 실제 모델/Windows 검증 여부는 별도로 기록합니다.
